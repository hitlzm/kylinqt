# 串口发送延迟测试方案（图像导引头 / 激光导引头 / 转台）

## 1 指标与测量口径

**串口发送延迟**：从操作员在界面上点击发送按钮起，到这一帧数据真正被写入串口为止的时间间隔。

| 打点 | 位置 | 取值 |
|---|---|---|
| T1 | 主线程。图像/激光取 `buildFrame()` 首行；转台取 7 个人工入口信号发射的瞬间 | 操作员点击生效的那一刻 |
| T2 | 工作线程，本次请求**第一次**写入串口之前 | 真正 write 的那一刻 |

**发送延迟 = T2 − T1**

两点都取本机单调时钟（进程内唯一的 `QElapsedTimer` + `nsecsElapsed()`，纳秒分辨率），
主线程与工作线程共用同一参考点，因此**不需要对时**，差值是可直接比较的。

### 1.1 覆盖的范围

点击按钮 → 主线程构帧 → 跨线程排队 → 工作线程取出请求 → 定时等待 → 第一次 `write()`

### 1.2 不覆盖的范围（报告里必须写明）

- **不包含** `write()` 返回之后的部分：数据还在驱动缓冲里，115200 下 224 字节一帧
  上线约 19.4 ms，460800 下约 4.9 ms。要测"真正出线"需要逻辑分析仪测 TX 引脚。
- **不包含**操作员反应时间。
- **只测人工点击**。自动发送源不打点，详见 2.3。

## 2 探针设计

实现：`utils/sendlatencyprobe.h` / `.cpp`。

### 2.1 三条链路的结构

| | 图像导引头 | 激光导引头 | 转台 |
|---|---|---|---|
| 点击侧 | `ImageSendData::buildFrame()` | `LaserSendData::buildFrame()` | `TurntableSendDataHex::buildFrame(index)` |
| 跨线程信号 | `requestSendData` | 同左 | `requestSendProgramMode` |
| 工作侧 | `SerialPortImage::onSendData` | `SerialPortLaser::onSendData` | `sendProgramMode` / `openTurntable` … |
| 定时器 | 20 ms × 10 拍 | 10 ms × 10 拍 | **无定时器** |
| 写入点 | `SerialPort::send()` | `SerialPort::send()` | `SerialPortTurntableHex::buildAndSend()` 里的 `m_serialPort->write()` |

图像/激光一次点击会写 10 拍（第 2~10 拍是补发），**只统计第一拍**。
转台没有定时器，点击后排队出来直接写；程控"发送数据"一次点击可能写 1 帧
（单轴）或 3 帧（三轴联动），同样**只统计第一帧**。

### 2.2 转台的打点入口（T1）

**只测程控"发送数据"这一个入口**，在 `main.cpp` 的 connect 附近旁挂，
以 `turntableSendData` 作 context，lambda 在主线程随信号发射同步执行：

| 入口 | QML 按钮 | 一次点击写几帧 |
|---|---|---|
| `requestSendProgramMode`（由 `buildFrame(index)` 发出） | 程控"发送数据" | 1（单轴）或 3（三轴联动） |

该信号本身没有函数体可插，所以只能旁挂；代价是起点取在"信号发射瞬间"，
比 `buildFrame` 入口晚几微秒（图像/激光取的是函数首行）。

**其余转台入口一律不打点**：使能 / 释放 / 停车 / 回零 / 复位 / 正弦运动。
它们仍然会写串口，但点完不会产生样本——如果需要其中某一个的数字，
照 `requestSendProgramMode` 的样子在 `main.cpp` 里补一条连接即可。

### 2.3 配对规则

`markClick` 把点击时刻压进该通道的等待队列；`markSend` 在第一次写入前弹出一个时刻算差。
三条规则覆盖所有情况：

1. **新点击重新武装**：每次 `markClick` 都清掉"已取样"标志，所以下一次写入重新取一个样本。
2. **同一次请求只取一帧**：取过样后，1 秒内的后续帧视为补发拍，不再产生样本（计入 `coalesced`）。
   这个有效期是必要的——图像一次点击的补发拍横跨 200 ms，而自动帧可能几分钟才来一次，
   不设期限的话自动帧会被错记成补发帧。
3. **过期令牌丢弃**：等待超过 500 ms 仍未配对的令牌直接丢弃（计入 `stale`），
   这样"请求在中途被丢弃"不会让后面的样本错配到很久以前的点击上。

### 2.4 只测人工点击

下列自动发送源**不打点**，它们在主线程找不到配对的点击令牌，落到 `unmatched` 计数里，
不进入样本：

- 每 10 分钟一次的时间同步帧（`sendTimeSyncFrame()`）——用 `m_timeSync` 判定并跳过。
- 图像导引头的偏差像素帧（`ImageSendData::buildDeviation`，由点击视频区域触发）。
- 转台的自动来源：外引导跟踪帧（`sendTrackMode_1s` / `sendTrackMode_5ms`，来自
  图像/激光/CCD 的 `reqExsend_*`）、时间同步（`sendTimesync` ← `reqTimesync`）、
  手柄遥控（`sendHandleMode` ← `handleModeSignal`），以及转台其余的人工入口
  （使能 / 释放 / 停车 / 回零 / 复位 / 正弦运动）。

转台的自动来源与人工入口共用同一个写入点 `buildAndSend`，所以它们**会被**
`markSend` 看到，但因为没有配对令牌，只会累加 `unmatched`，不会产生样本。

因此**测量时 `unmatched` 应当保持 0**；若非 0，说明有自动帧在跑，测试环境不干净。

### 2.5 计数桶怎么读

| 计数 | 含义 | 期望值 |
|---|---|---|
| `samples` | 有效样本数 | = 点击次数 |
| `coalesced` | 同一次点击的后续帧 | 图像/激光 = 9 × 点击次数；转台 = 三轴联动时 2 × 点击次数（单轴程控为 0） |
| `unmatched` | 无对应点击的写入（自动源） | 0 |
| `dropped` | 请求被丢弃（串口未打开等） | 0 |
| `stale` | 过期令牌 | 0 |

`samples` 与 `coalesced` 的关系是免费的自检：图像/激光都是每次点击 1 + 9 拍；
转台按 2.2 核对，三轴联动每次点击应产生 `+1` 样本、`+2` 补发帧。

## 3 使能开关

**默认关闭**，关闭状态下热路径上只有一次 relaxed 原子读，随即返回，不构造对象、
不加锁、不分配内存。交付版本与原来行为一致。

| 级别 | 机制 | 说明 |
|---|---|---|
| 编译期总闸 | `SENDLAT_COMPILED=0` | 打点代码完全剥离，调用点编译成空函数 |
| 编译期默认 | `SENDLAT_DEFAULT_ON=1` | 默认 0；一般不用改 |
| 运行时 | `KYLIN_SENDLAT=1` | 无需重新编译即可启用 |
| 运行中 | `SendLat::setEnabled(true/false)` | 随时开关；切换时清空配对状态 |

环境变量一览：

```
KYLIN_SENDLAT=1            启动即启用（1/true/on/yes；默认 0）
KYLIN_SENDLAT_VERBOSE=0    关闭逐条打印（默认开启，每次点击打印一行）
KYLIN_SENDLAT_EVERY=50     每积累 N 个样本打印一次汇总，0 = 不打印
KYLIN_SENDLAT_CSV=<路径>   把原始样本落盘成 CSV
```

## 4 输出

逐条（默认开启）：

```
[SendLat] image  #12  latency = 20.634 ms
```

汇总（每 N 个样本、关闭开关时、进程退出时各一次）：

```
[SendLat] image  samples=50  avg=20.63ms  p50=20.55  p95=22.10  p99=27.31
                 min=20.11  max=28.40  coalesced=450  unmatched=0  dropped=0  stale=0
```

输出刻意使用 ASCII，终端代码页不影响，也方便 grep 与粘贴进报告。

CSV 列：`channel,index,send_latency_ms`

## 5 测试步骤

1. 打开对应串口（图像 / 激光 / 转台，测哪条开哪条）。
2. 用 `KYLIN_SENDLAT=1` 启动程序（或运行中调用 `SendLat::setEnabled(true)`）。
   终端应出现 `[SendLat] probe enabled`。
3. **确认 `unmatched` 保持 0**：退出外引导模式、断开手柄遥控、
   测试期间不要点击视频区域发偏差像素。
4. 点击"发送数据"按钮若干次（建议 ≥ 50 次以便看 P95/P99）。
   转台只测程控"发送数据"按钮；选三轴联动时每次点击应 `+1` 样本、`+2` 补发帧，
   单轴时补发帧为 0。其余转台按钮点下去不产生样本，属正常。
5. 需要 CSV 时用 `KYLIN_SENDLAT_CSV=/tmp/sendlat.csv` 启动，测试结束（退出程序）后取文件。
6. 退出程序，终端会打印一次最终汇总。

## 6 结果判读

### 6.1 预期数值

| 通道 | 预期 | 主要构成 |
|---|---|---|
| 图像导引头 | **20.1 ~ 21 ms** | 20 ms 定时等待占绝对主导 |
| 激光导引头 | **10.1 ~ 11 ms** | 10 ms 定时等待占绝对主导 |
| 转台 | **0.05 ~ 1 ms** | 无定时等待，只有排队 + 工作线程唤醒 + 构帧 |

图像/激光都存在"点击后先等一个定时周期再发第一拍"的实现
（`timer->setInterval(N); timer->start();`），所以**定时周期就是这两条链路的硬地板**。
有用的信息在余量里：

> 链路开销 = 测量值 − 定时周期

余量反映的是主线程构帧 + 跨线程排队 + 工作线程唤醒 + 事件循环调度的总代价，
典型 0.05 ~ 0.5 ms；P99 会明显高于中位数，那部分是调度抖动。

转台没有定时等待，所以它的测量值**本身就是这个余量**——三条链路里只有转台的数字
直接反映链路开销。反过来说，转台对 CPU 争用、工作线程被接收解析占住更敏感，
尾部会比图像/激光更长。

**自检线**：如果测出来明显低于定时周期（图像 < 20 ms、激光 < 10 ms），
说明打点位置或启用时机有问题，需要复查。

### 6.2 已知的测量扰动

1. **逐帧 hex 打印**。图像 `SerialPortImage::onSendData` 里那行
   `qDebug() << data.toHex()` 排在 `markSend` 之前，它的开销**会被计入延迟**
   （449 字符的十六进制串 + 格式化）。要拿干净数字，测两轮对比：

   | 轮次 | 做法 | 用途 |
   |---|---|---|
   | A | 原样运行 | 反映操作员实际感受的延迟 |
   | B | 关掉逐帧 hex 打印 | 扣掉日志开销后的链路延迟 |

2. **探针自身的打印**。`markSend` 在取样、解锁之后才打印，所以**记录到的样本值不受打印影响**，
   但那一拍的写入会被打印耗时略微推后。逐条打印用 `KYLIN_SENDLAT_VERBOSE=0` 可关。

3. **定时器抖动**。`Qt::PreciseTimer` 在 20 ms 上的实际到期时刻通常有 0~1 ms 的偏差，
   Linux 下由事件循环的 poll 超时粒度决定。

| 文件 | 内容 |

| `tests/sendlatency_probe_selftest.cpp` | 配对规则自检，不参与主程序构建 |

自检程序编译运行（Qt 路径按本机改）：

```
g++ -std=gnu++14 -I<Qt>/include -I<Qt>/include/QtCore \
    tests/sendlatency_probe_selftest.cpp utils/sendlatencyprobe.cpp \
    -L<Qt>/lib -lQt5Core -o sendlat_selftest.exe
```

它验证的是配对规则（样本数 / 补发帧 / 未配对 / 丢弃 / 过期 / 开关生效），
不验证绝对时延。
