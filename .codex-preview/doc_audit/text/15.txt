[body][Heading 2][inherit] 1.2  系统概述
[body][Normal][inherit] 1. 计算机系统的用途
[body][Normal][inherit] 本软件运行于方舱上位机，完成图像DYT和激光DYT数据接收、CCD 串口控制与视频显示、北斗 RMC 时间/位置接收、三轴转台控制、六自由度平台 UDP 控制、手柄输入、视频显示与录制，以及图像、激光、转台三路 CSV 数据保存。图像和 CCD 视频可按外引导条件启用 YOLO 目标检测；程控模式可导入 CSV 跟踪点并以 20 ms 周期下发转台。界面和硬件访问由同一桌面进程承担，不设置独立服务端。
[body][Normal][inherit] 2. 本软件在系统中的位置
[body][Normal][inherit] 主程序 main.cpp 创建数据对象、串口工作对象、模式控制器、数据记录器、认证与日志对象，并通过 QQmlApplicationEngine 加载 main.qml。登录成功后，QML 才实例化主界面并调用 beginStartup。随后 C++ 启动图像、激光、转台、北斗、手柄五个工作线程和一个视频处理线程；CCD 串口对象固定在主线程。
[body][Normal][inherit] 3. 编程工作的范围
[body][Normal][inherit] 维护工作集中在主程序文件、components 下的界面、serialport 下的串口与协议、network 下的 UDP 客户端、vlcvideo 下的视频组件、opencv 下的视频处理、record 下的数据保存，以及 auth、log、ModeControl、kalman、utils 等目录。倾角仪串口和模板装订网络在 main.cpp 中已停用，相关源码或界面文件仅作保留。本文档不覆盖操作系统内核、串口驱动和设备固件开发。

[body][Heading 2][inherit] 3.2  操作信息
[body][Normal][inherit] 本节按附录 R 3.2 条列出与本工程有关的操作特性。下列性质以交付目标平台为主，当前 Windows/MinGW 开发构建用于编码、界面和多数功能验证；凡涉及时序、字节序、线程调度或图形后端的内容，必须在最终目标平台上复测。
[body][Normal][inherit] a) 时钟周期：项目资料采用 2.3～2.6 GHz 量级的处理器。软件不依赖固定周期估算业务时间，超时和周期由 QTimer、QElapsedTimer、设备返回时标和 QDateTime 共同构成。当前接口标称周期为：图像和激光每 20 ms 一帧，转台状态每 5 ms 一帧，六自由度状态查询每 200 ms 一次。时延测试工具位于 utils/，通过实测而非指令周期推算。
[body][Normal][inherit] b) 字长：交付目标为 64 位 AArch64，当前开发构建为 64 位 x86_64。协议字段和位操作使用 Qt 的 qint8/quint8、qint16/quint16、qint32/quint32、qint64/quint64，或 <cstdint> 定长类型；不得用 long 表示外部协议宽度。图像和激光接收结构体使用 #pragma pack(push,1)，修改字段时必须核对 sizeof、字节偏移和跨平台对齐。
[body][Normal][inherit] c) 内存：项目资料中的上位机内存为 8 GB 量级。主要动态占用来自 libmpv 解码、OpenCV 图像处理、ONNX 推理、视频帧副本和 CSV 保存缓冲。当前代码没有统一的进程内存上限；排查内存问题时应结合任务管理器、top/ps、qDebug 输出和现有延迟探针，先确认瓶颈在解码、推理、渲染还是文件写入。
[body][Normal][inherit] d) 指令集：交付目标为 ARMv8-A AArch64，当前开发机为 x86_64。源码没有汇编文件，业务代码依赖编译器生成目标指令。NEON/ASIMD、缓存行和 AArch64 寄存器内容只适用于目标构建，不应用于推断当前 Windows 构建的代码行为。
[body][Normal][inherit] e) 中断能力：应用不直接处理硬件中断，也不注册设备中断服务程序。串口通过 QSerialPort::readyRead 进入 Qt 事件循环，UDP 通过 QUdpSocket::readyRead 处理，视频事件由 libmpv 唤醒并在主线程事件循环中分派。
[body][Normal][inherit] f) 操作方式：软件为交互式桌面程序，启动时先显示登录页；认证成功后由 QML 调用 beginStartup，main.cpp 才创建并启动硬件相关线程。运行期包含图像、激光、转台、北斗、手柄五个串口/输入工作线程，一个 StreamProcessor 视频处理线程，以及主线程中的模式控制、六自由度 UDP、CCD 串口、视频显示和记录对象。
[body][Normal][inherit] g) 操作寄存器：应用运行在用户态，不直接访问系统寄存器。设备状态通过 QSerialPort、QUdpSocket、libmpv API 和文件系统获取，不需要手工维护浮点状态寄存器。
[body][Normal][inherit] h) 错误指示：Qt 对象通过 errorOccurred、portError、popupMessage、lastError 等信号报告错误；LogManager 在界面保留最多 500 条、按 200 ms 节流的外引导跟踪日志，qDebug/qWarning 写入终端或开发环境输出。工程没有统一的数字错误码表，界面提示和数据层错误需结合信号名称、串口错误串、帧头/校验信息和 qDebug 上下文定位。SIGSEGV 等进程级异常由操作系统处理，当前代码不安装自定义信号处理函数。
[body][Normal][inherit] i) 输入输出：串口设备通过 QSerialPort 访问，统一配置为 8 数据位、无校验、1 停止位、无流控；六自由度平台通过 QUdpSocket 广播收发；视频通过 libmpv 打开 RTSP、UDP 或其他 mpv 支持的 URL；数据通过 QFile 写入 CSV；QML 与 C++ 通过上下文属性、Q_PROPERTY、Q_INVOKABLE 和信号槽交互。
[body][Normal][inherit] j) 特殊特征：协议字节序并不统一。图像接收帧为 156 字节，帧头 0x77 0xAB，CRC16-CCITT 多项式 0x1021、初值 0x0000、不反射，字段按小端读取；图像发送帧为 224 字节。激光接收帧为 48 字节、发送帧为 26 字节，帧头 0x55 0xAA 0xDC，字段按大端读取，末字节为异或校验。转台命令帧 19 字节、状态帧 29 字节，帧头 0x55 0xAA，多字节字段按大端，状态帧校验为 bytes 2～26 累加和。修改协议代码时必须逐字段核对字节偏移，不得假设三类设备共用一种编码。
[body][Heading 2][inherit] 3.3  编译、汇编和连接
[body][Normal][inherit] a) 编译与汇编：源码不含 .s/.S 汇编文件，C++14 和 QML 由编译器及 Qt 工具链处理。反汇编只用于排查编译器输出、协议结构布局和崩溃地址，不作为发布源码的组成部分。
[body][Normal][inherit] b) 编译程序与版本：当前仓库验证工具链为 MinGW-W64 g++ 7.3.0，编译标志为 -std=gnu++14；CMakeLists.txt 要求 CMake 3.16 及以上，现有构建缓存由 CMake 4.1 生成，生成器为 MinGW Makefiles。交付目标 AArch64 的编译器、sysroot 和 Qt 套件在仓库中尚未固化，须由交付构建环境提供并在目标机复测。
[body][Normal][inherit] c) 连接程序与库：CMake 查找 Qt5 Core、Quick、Gui、SerialPort、Gamepad、Network、Widgets、QuickControls2，链接 libmpv、OpenCV，可选链接 ONNX Runtime；Windows 还链接 ws2_32。当前构建只生成一个 kylinqt 可执行目标，没有把业务代码拆成多个动态库。
[body][Normal][inherit] d) 编译与链接选项：当前 Debug 构建实际使用 -g、QT_QML_DEBUG 和 QT_DECLARATIVE_DEBUG；C++ 标准由 CMAKE_CXX_STANDARD=14 设置。工程没有配置 -Wall、-Wextra、-Werror、-ffast-math、自定义 rpath 或统一的异常关闭选项。编译选项修改应同步维护 CMakeLists.txt，并在目标构建中重新验证。

[body][Normal][inherit] e) 构建流程：在新构建目录执行 CMake 配置和构建。AUTOMOC、AUTOUIC、AUTORCC 自动处理元对象、界面和资源；qml.qrc 把主界面资源编入程序。构建后，CMake 只自动复制 OpenCV、libmpv 和可选的 ONNX Runtime DLL，不会自动执行 Windows 的 windeployqt，也不会生成校验清单。

[body][Heading 1][inherit] 4  编程信息
[body][Heading 2][inherit] 4.1  编程特征
[body][Normal][inherit] 本节说明本工程实际涉及的 C++、Qt 和平台特征。AArch64 数据布局、调用约定和指令类别用于交付目标阅读；当前 Windows/MinGW 构建的 ABI 与之不同。
[body][Normal][inherit] a) 数据表示：协议解析使用 Qt 定长整数和显式移位拼接。图像与激光接收代码还存在按结构体布局读取帧的方式，修改结构体时必须检查编译器对齐、固定长度和字节序；跨接口传输的数据不得直接依赖 bool 的位模式。
[body][Caption][inherit] 表 7  基本数据类型的长度与对齐
[body][Normal][inherit] b) 指令格式与寻址：交付目标为 AArch64 时，C++ 数组和结构体访问由 GCC 生成加载/存储及地址计算指令。当前开发构建为 x86_64，不能通过阅读 Windows 反汇编推断目标平台寄存器分配。影响代码移植的主要因素是结构体填充、长整型宽度和字节序。
[body][Normal][inherit] c) 专用寄存器：本软件不直接使用架构寄存器。AArch64 上的 x29/x30、SIMD 寄存器和平台保留寄存器由编译器及运行库管理。需要平台级优化时，应在目标构建中通过性能测量确认，不手工绑定寄存器。
[body][Normal][inherit] d) 调用约定：Qt 信号槽、QObject 元对象、QThread::moveToThread 和跨线程 QueuedConnection 是主要调用边界。跨线程对象必须以 QObject 及其信号槽传递，不通过裸函数指针或跨线程直接访问 QML 对象。目标 AArch64 构建遵循 AAPCS64，当前 x86_64 构建遵循 MinGW/Win64 ABI。
[body][Caption][inherit] 表 8  调用约定与寄存器用途（AAPCS64 摘要）
[body][Normal][inherit] e) 子程序与过程：业务对象以 QObject 派生类实现，参数通过值、const 引用或 Qt 元类型信号传递。main.cpp 将串口工作对象移动到工作线程，数据对象保留在主线程；ImageData、LaserData、TurntableDataHex、BDData、CCDData、ModeController、DataRecorder 和 SixDofMotionClient 通过上下文属性暴露给 QML。
[body][Normal][inherit] f) 异步事件：Qt 的 readyRead、timer、signal/slot 和 libmpv 的 update callback 构成主要异步模型。串口工作线程只负责 I/O 与解析，解析结果通过 QueuedConnection 回主线程；视频渲染通过 QQuickFramebufferObject 与渲染线程交互。
[body][Normal][inherit] g) 定时器与时钟：周期任务使用 QTimer，高精度测量使用 QElapsedTimer；业务时间来自设备返回时标、北斗 RMC、转台毫秒时间或本机 QDateTime。图像和激光在返回时标无效时回退本机时间，转台保存协议毫秒时间，各来源不能假定天然同步。
[body][Normal][inherit] h) 内存保护：用户态不能自定义 MPU/MMU 保护。串口和 UDP 解析器必须先积累完整报文、检查长度和校验，再按固定偏移访问。图像、激光和转台接收缓冲在 readyRead 中追加数据并查找帧头，半帧需保留到下一批数据。
[body][Normal][inherit] i) 其他特征：视频原始帧、OpenCV 推理结果和 UI 帧副本是主要大块内存访问对象；保存采用 200 ms 文本缓冲；视频录像采用 mpv record-file 写 TS 后由 ffmpeg 流复制为 MP4。性能优化应先使用现有延迟探针和 qDebug/top 数据确认瓶颈。

[body][Heading 2][inherit] 4.3  输入和输出控制
[body][Normal][inherit] a) 设备输入：图像帧通过串口工作线程的 readyRead 累积，按 0x77 0xAB 帧头切出 156 字节接收帧并执行 CRC16-CCITT（多项式 0x1021、初值 0x0000）；激光帧按 0x55 0xAA 0xDC 帧头切出 48 字节接收帧并执行异或校验；转台帧按 0x55 0xAA 帧头切出 29 字节并执行 bytes 2～26 累加校验；北斗只解析 $GBRMC/$BDRMC 的 RMC 语句。各接收缓冲都保留半帧，不假设一次 readyRead 对应一帧。
[body][Caption][inherit] 表 10  串口与主要接口参数
[body][Normal][inherit] b) 程序加载与校验：程序镜像由操作系统加载，软件不在运行期校验自身。当前仓库不读取 INI/JSON 配置文件；串口、波特率、视频 URL、六自由度网络参数等由界面选中值或代码默认值提供。修改默认值后须重新构建并执行接口回归。运行期校验的对象是设备帧的帧头、长度和校验，以及视频播放器和 UDP 链路的运行状态。
[body][Normal][inherit] c) 数据通道：当前使用图像串口 460800 bps、激光串口 115200 bps、转台串口 230400 bps、北斗和 CCD 控制串口 9600 bps（均以界面选项为准）。图像和激光标称 20 ms 一帧，转台状态标称 5 ms 一帧；六自由度平台使用 QUdpSocket，默认本机 8080、运动广播 192.168.15.255:7408、状态广播 255.255.255.255:8081，状态查询周期 200 ms。
[body][Normal][inherit] d) 离散输入输出：手柄通过 Qt Gamepad 枚举，由 GamepadBridge 把左右摇杆、扳机、A/B 按键转成 Qt 信号，经 QueuedConnection 送入 Myhandle 工作线程；遥控模式每 20 ms 发送一次手柄状态。界面按钮和开关通过 QML 调用槽函数，输出指示灯和状态文字由 QML 属性绑定，不在串口线程直接修改界面对象。
[body][Normal][inherit] e) 接口部件：主要接口包括 Qt Serial Port、QUdpSocket、libmpv 视频 URL、Qt Quick OpenGL 渲染上下文和本地文件系统。串口端口由 QSerialPortInfo 扫描后在界面下拉框选择，网络地址默认值位于 SixDofMotionClient，视频 URL 位于视频组件；当前没有统一配置管理模块，也没有固定 udev 映射文件。
[body][Normal][inherit] f) 设备操作码：转台命令码定义在 serialport_turntable_HEX.h，包括 CMD_ENABLE、CMD_STOP、CMD_ZERO、CMD_POSITION、CMD_SPEED、CMD_SWING、CMD_TRACK_250、CMD_TRACK_20MS、CMD_CORRECTION 等；图像和激光发送字段定义在各自发送结构体中。新增或修改协议常量时，应同步更新发送构帧、接收解析、界面显示和测试用例。

[body][Normal][inherit] 示例 1 展示串口按字节流收帧。串口一次 readyRead 可能只到达半帧，因此必须保留缓冲、查找帧头、按定长切帧。激光接收结构体当前为 48 字节，使用三重帧头 0x55 0xAA 0xDC；图像接收帧为 156 字节，帧头 0x77 0xAB；转台状态帧为 29 字节，帧头 0x55 0xAA。
[body][Normal][inherit] void SerialPortLaser::onReadyRead()
{
    m_rxBuffer.append(m_serialPort->readAll());
    const int frameLen = static_cast<int>(sizeof(laser_recv_frame));
    while (m_rxBuffer.size() >= 3) {
        int i = m_rxBuffer.indexOf(QByteArray("\x55\xAA\xDC", 3));
        if (i < 0) { m_rxBuffer = m_rxBuffer.right(2); break; }
        if (i > 0) m_rxBuffer.remove(0, i);
        if (m_rxBuffer.size() < frameLen) break;
        const QByteArray frame = m_rxBuffer.left(frameLen);
        m_rxBuffer.remove(0, frameLen);
        parseData(frame);
    }
}
[body][Normal][inherit] 示例 2 展示不同协议的校验与字节序。图像接收帧使用 CRC16-CCITT 比对，当前代码的多项式为 0x1021、初值为 0x0000、不反射；激光协议使用异或校验，接收字段按大端解释；转台状态帧的校验为 bytes 2～26 累加和，多字节字段按大端。不能把某一个设备的校验规则复用到其他设备。
[body][Normal][inherit] // CRC16-CCITT：初值 0x0000，多项式 0x1021，不反射（与图像DYT协议一致）
static quint16 crc16_ccitt(const quint8 *p, int n)
{
    static quint16 tab[256]; static bool init = false;
    if (!init) {
        for (int i = 0; i < 256; ++i) {
            quint16 c = quint16(i) << 8;
            for (int k = 0; k < 8; ++k)
                c = (c & 0x8000) ? quint16((c << 1) ^ 0x1021) : quint16(c << 1);
            tab[i] = c;
        }
        init = true;
    }
    quint16 crc = 0x0000;
    for (int i = 0; i < n; ++i)
        crc = quint16((crc << 8) ^ tab[((crc >> 8) ^ p[i]) & 0xFF]);
    return crc;
}

// 图像字段按小端解释；激光和转台字段按大端解释
static inline qint16 le16s(const quint8 *p)
{ return qint16(quint16(p[0]) | (quint16(p[1]) << 8)); }
